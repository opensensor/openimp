# OpenIMP test pattern

An extension beyond the vendor IMP API (all SoCs). A synthetic picture with a known content
is fed into the pipeline instead of (or generated by) the sensor, so that encoder, scaler,
rotation, JPEG, IVS and the ISP can be checked against a known ideal picture, with or without
a real scene. Default off, behaviour neutral when off (one integer compare per frame).

![Pattern logo preview (synthetic)](assets/testpattern-logo-preview.png)

Header: `include/openimp_testpattern.h` (ABI 1). Detect support with the symbol
`OpenIMP_Cap_TestPattern` (absent on a vendor libimp: use `dlsym` or a weak reference).

## Modes and what they cover

| Mode | Name | Picture | Pipeline part covered |
|---|---|---|---|
| 0 | off | real sensor picture | none |
| 1 | pattern | grey ramp, checkerboard (16/235), colour bars, OpenIMP logo in the middle on a white quiet zone | **after the ISP**: FrameSource output, scaler (ch1), rotation (I2D), OSD, encoder (H.264/H.265/JPEG), VUI/range signalling |
| 2 | moving | pattern + black square bouncing at `step` px/frame + 16 bit frame counter (top left, 16x16 cells, MSB first) | as mode 1, plus drops, duplicates, reordering, smearing, rate control behaviour under a changing frame |
| 3 | motion test | flat grey with +-1 LSB noise, logo, frame counter, objects of given size, contrast and speed (one built-in object or a script) | as mode 2, and the pattern also reaches **IVS** (motion detection input); the objects have a known time and place |
| 4 | sensor pattern | the sensor outputs its own built-in test pattern; frames are not replaced | **through the whole ISP** (BLC, WB, CCM, gamma, NR, scaler, encoder), pattern content depends on the sensor |
| 5 (planned) | ISP input / RAW | known Bayer picture from DDR or the Apical test generator | through the whole ISP with a known picture; not implemented in the API yet (see status table) |

Modes 1-3 replace each captured NV12 frame on the way to the encoder (T20-T31 in the capture
path of `kernel_interface.c`, mode 3 before IVS; T40/T41 in the FrameSource path before the IVS
feeder), so the sensor and the ISP keep running and only provide the clock. The channel size
decides the picture size, every channel gets its own counter. Mode 4 does not touch frames: it
sets a test pattern bit in the sensor (register table per sensor, written through the ISP sensor
register ioctl; the chip ID is read first and the write is verified by a readback).

## API

```c
#include "openimp_testpattern.h"

OpenIMPTestPatternParams p;
OpenIMP_TestPattern_ParamsInit(&p);     /* defaults, size set */
p.step = 8;                             /* mode 2 */
OpenIMP_TestPattern_Set(OPENIMP_TP_MOVING, &p);   /* p == NULL keeps the parameters */

OpenIMPTestPatternState s = { .size = sizeof s };
OpenIMP_TestPattern_Get(&s);            /* mode, frames, objects_shown, objects_active, params */
OpenIMP_TestPattern_Set(OPENIMP_TP_OFF, NULL);
```

- `OpenIMP_TestPattern_Set(mode, params)`: returns 0, or -1 with `EINVAL` (mode, range, size);
  mode 4: `ENOTSUP` (no table entry for the sensor), `EIO` (register access failed, sensor not
  running). May be called at any time, also while streaming; the next frame uses the new state.
  Set restarts the frame counter, the object clock and the frames/objects counters.
- `OpenIMP_TestPattern_Get(state)`: `state->size` must be set. Returns the mode, the active
  parameters, frames replaced since the last Set, mode 3 objects shown and visible now.
- `OpenIMP_TestPattern_SensorInfo(name, reg, mask, desc)`: sensor name, test pattern register,
  mask and a short description of the running sensor (mode 4).
- ABI: both structs start with a `size` field set by the caller. New fields are only appended;
  Set pads a shorter caller struct with defaults, Get fills at most the caller's size.
- Thread safe, no lock in the frame path (parameters are double buffered, mode and epoch are
  atomic; a frame takes one relaxed load and, when active, a ~190 byte parameter snapshot).

Parameters (`OpenIMPTestPatternParams`):

| Field | Mode | Meaning, default |
|---|---|---|
| `step` | 2 | square speed in px/frame, even, >= 2, 8 |
| `logo` | 1-3 | `OPENIMP_TP_LOGO_OPENIMP` (default) or `_NONE` |
| `noise` | 3 | peak noise in LSB per frame, 1 |
| `obj_size` | 3 | built-in object edge in px of a 640 px wide frame (scaled with the width), 0 = none |
| `obj_contrast` | 3 | added to Y inside the object, -200..200, 40 |
| `obj_speed` | 3 | px/s of a 640 px wide frame, 0 = static |
| `obj_cell_x/y` | 3 | grid cell of the 8 x 6 grid, 1,1 |
| `obj_on_ms`, `obj_period_ms` | 3 | visible for `on` every `period` (0 = always), 3000 / 6000 |
| `script` | 3 | object script file, lines `t=<s> cell=<cx>,<cy> size=<px> contrast=<dY> [dur=<s>] [speed=<px/s>]`; time counts from the Set; empty = `OPENIMP_TEST_PATTERN_EVENTS` or `/tmp/openimp_tp_events` |
| `ae_hold` | 4 | 1 (default): AE frozen at the values of the moment mode 4 starts; 0: AE keeps running |
| `awb_hold` | 4 | 0 (default): AWB keeps running; 1: AWB gains frozen (colour measurement) |

Leaving mode 4 clears the sensor bit (read-modify-write, correct also after a sensor restart)
and restores AE/AWB to the state before mode 4. Hold implementation per SoC: T23/T31
`SetAeFreeze`; T21 a new driver control (0x8000034, sensor exposure/gain are no longer queued);
T20 manual exposure with the gain ceiling at the current gain; T40/T41 manual AE mode / AWB
freeze (implemented, not device-tested).

## Control from outside: environment, socket, tpctl

- `OPENIMP_TEST_PATTERN=0..3`: start value (mode 4 needs a running sensor, use Set).
  `OPENIMP_TEST_PATTERN_STEP`, `OPENIMP_TEST_PATTERN_NOISE`, `OPENIMP_TEST_PATTERN_EVENTS`
  set the mode 2/3 parameters at start.
- `OPENIMP_TEST_PATTERN_CTL=<socket path>`: the library opens a datagram socket (default
  client path `/tmp/openimp_tp_ctl`) in the process that loaded it. Text commands `get` and
  `set <mode> key=value ...`.
- `tools/testpattern/tpctl` (target tool, abstract client address, leaves no files):

```
tpctl get
tpctl set <0..4> [step=N] [logo=0|1] [noise=N] [obj_size=N] [obj_contrast=N] [obj_speed=N]
                 [obj_cell=X,Y] [obj_on_ms=N] [obj_period_ms=N] [script=PATH]
                 [ae_hold=0|1] [awb_hold=0|1]
```

Prints the state after the call; exit 0 on "ok", 1 on error, 2 no answer. Examples:
`tpctl set 1`, `tpctl set 2 step=16`, `tpctl set 3 obj_size=32 obj_contrast=48 obj_speed=60`,
`tpctl set 4 ae_hold=1 awb_hold=1`, `tpctl set 0`.

## Use in a streamer (timps)

timps 1.10.3 and newer (`dev` branch) expose the pattern through `/control testpattern` and
buttons in the WebUI (off, pattern, moving, motion, sensor pattern). For mode 4 a day/night
hold is available, so that a day/night switch during a measurement does not change the picture.
A streamer only needs `OpenIMP_Cap_TestPattern` to detect support and the two calls above;
`tpctl` works for processes that do not integrate the API (set `OPENIMP_TEST_PATTERN_CTL`).

## Host evaluation (`tools/`)

All host tools share the generator `src/openimp_testpattern_gen.h`, so the ideal picture
(including the logo) is exactly what the camera draws.

- `tools/testpattern/tbcmp.c`, `ana.sh`: decoded frame against the ideal: PSNR Y/U/V, SSIM Y,
  mean level per colour bar, ramp ends, checkerboard levels (16/235).
- `tools/testpattern/tbmotion.c`, `anamotion.sh`: mode 2 stream: reads the counter from the
  decoded picture, builds the expected picture, PSNR/SSIM per frame, position error of the
  square, ghost pixels in the square's row band, drops/dups/reorder, I/P statistics, bit rate.
- `tools/testpattern/mklogo.py`: rasterises `docs/assets/banner.svg` to the palette + RLE logo
  header (host build step only; no SVG parser on the camera).
- `tools/rawcheck/rawcheck` (camera) and `rawana` (host): FrameSource/SnapFrame raw layout (pitch
  from the vertical smoothness of the luma, chroma start by edge fit or exact comparison with `-s`,
  plane boundaries). Found and fixed the SnapFrame NV12 chroma offset for heights not divisible by 16.
- `tools/motiontest` (camera, IVS Move on 48 ROIs) and `mtana.py` (host): hits, latency, false
  alarms and a sensitivity curve against the mode 3 event log (`[TP] ev <i> start|stop <ms>`);
  `v2sim` / `v2replay`: motion v2 algorithm on the host with the mode 3 sweep or a recorded
  analysis trace (no camera needed).
- `make check` runs `tests/testpattern` (API semantics, ABI shortening, picture properties, ctl
  socket, sensor table with a fake sensor).

Typical results (2026-10-19, roitest FixQP 24): mode 1 H.264 PSNR Y 51-67 dB, colour bar error
0/0 (U/V), checkerboard exactly 16/235, no colour swap, no orientation or block errors, I2D 90 is
a clockwise rotation; JPEG PSNR Y 51-56 dB, U/V off by 1 at small chroma values (quantisation, as
the hardware JPEG reference). Mode 2: 0 drops, 0 duplicates, 0 reorder, position error 0.
Encoder range signalling: H.264 `video_full_range=0` matches the ISP output (limited), JPEG is marked
full range (JFIF) while the data are limited, so viewers show black as 16.

## Logo and size cost

The logo is the OpenIMP banner (dot grid, lettering, tagline), 384x118 master, 32 colour palette
plus RLE (3671 + 96 bytes), unpacked and scaled once per picture size (lock-free tile cache, 16
slots). The box is 15 % of the picture height (minimum 48 px), at most 60 % of the width, with a
quiet zone of 18 % of the logo height, white (Y 235). It lies in the checkerboard band; ramps and
bars stay unchanged outside the box, `logo_box()` gives the mask rectangle for evaluation.

Cost: +3.8 KB `.rodata`; about +8 KB of the xz compressed `libimp.so` (including the hook and the
control socket). The per-frame cost with the pattern off is one integer compare.

Legend: ✅ device-tested, 🔧 implemented, untested, ⏳ in progress, ❌ not possible per hardware

|---|---|---|---|---|---|---|---|---|
| Mode 1 pattern | ✅ | ✅ | ✅ | ✅ | 🔧 | ✅ | ✅ | ✅ |
| Mode 2 moving | ✅ | 🔧 | ✅ | ✅ | 🔧 | ✅ | ✅ | 🔧 |
| Mode 3 motion test | ✅ (objects shown) | 🔧 | ✅ | ✅ | 🔧 | ✅ | ✅ | 🔧 |
| Mode 4 sensor pattern | 🔧 (jxh42) | ✅ (jxf23) | ✅ (jxf23, sensor exposure hold) | ✅ (sc2336p) | 🔧 | 🔧 (register by hand ✅) | ⏳ (sc830ai) | ✅ gc5603 (colour bars, 72 s stable) / 🔧 sc5336 |
| Own picture before the ISP | 🔧 Apical TPG | ✅ Apical TPG + VIC colour bars (register level, not in the API yet) | ❌ | ❌ | 🔧 Apical TPG | ❌ (VIC bars, CSI, mux tested: no) | ❓ | ⏳ RAW from DDR (v3 module pending) |

Notes:

- Modes 2/3 on T20, T30, T41 were not run (camera unavailable or no build); mode 3 on T10 only
  shows the objects, detection was measured on T31/T23/T21/T40.
- T31 mode 4: the register write works by hand (sc4336p, 0x4501 bit 3); through the API the old
  installed driver returns EIO (the sensor register ioctl was a silent no-op, fixed in open-tx-isp
  `next`, T21/T23 fix device-tested with a test module; T31 needs the current module).
- Sensor pattern registers: SmartSens (sc2336, sc2336p, sc4336p, sc5336, sc830ai, sc1a4t) 0x4501
  bit 3, produces a Bayer ramp (after the ISP: black, magenta gradient, white, mirrored on T40);
  JX (jxf22, jxf23, jxh42) 0x0c bit 0, vertical colour columns. GalaxyCore gc5603 0x008c bit 0 (0x10 -> 0x11), colour bars/chart.
- Before the ISP: T41 has an ISP RAW read DMA (DDR to ISP, full picture, colour chart); the first
  two driver attempts crashed the ISP (the recovered open driver passes no control pointer and
  scales the register offsets by 4), the third module is untested. The Tiziano v1 ISP (T21, T23, T31)
  has no test generator and no RAW input: Apical (T10, T20, T30) has a test generator (`video_test_gen`,
  register 0x9c0 ...), proven on T20 by register writes. T20 VIC colour bars: `CB_MODE0/1`
  (0xb0/0xa0) = 0x80008000; on T21 the same write stalls the camera, on T31 (MIPI) the registers do not latch.

## Known limits

- Mode 3 does not detect **static** appearing objects by design: motion v2 (`min_move`) ignores an
  object that appears without moving (lamp or reflex flicker). Use `obj_speed > 0` (24-40 px at 640 wide),
  or `OPENIMP_MOTION_V2_MIN_MOVE=-1` for tests. 16 px objects are never detected at sensitivity 2
  (about 600 px area needed, as vendor).
- Objects larger than a grid cell (60 px at 640x360, `obj_size > 60`) are not drawn (open bug in `next`
  at the time of writing); moving objects only swing +-(cell width - size)/2.
- JX-F23 (T20, T21): the sensor driver rewrites register 0x0c at every analog gain step, which
  clears the pattern after about 1.5 s. Keep `ae_hold=1` (default) or call Set(4) again.
- gc5603 (T41): register found by I2C on the device (no source); the pattern is tiled by the scaler (3x3 bars), colours are off because the Bayer phase of the pattern differs.
- Mode 3 has no real sensor or ISP noise: false alarms under real noise are measured separately
  (a short static real scene), the pattern only has +-1 LSB.
- The hook assumes capture pitch = width on T20-T31 (measured at 1920, 640, 2560); odd widths not checked.
- Mode 4 in dark rooms: AE sits at maximum gain and the ramp saturates; measure in daylight or
  with a fixed exposure.
- Pictures with a real scene must not be published; use only the synthetic pattern pictures.
