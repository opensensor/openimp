# H.265 on T21 / T23: not available (vendor and hardware)

Status 2026-10-03: investigated before any implementation. Result: there is
no Helix H.265 path to reproduce. Neither the vendor libimp nor the SoC
offers HEVC encoding on T21 or T23, so OpenIMP keeps H.264 + JPEG only
there, like the vendor.

## Vendor libimp (T23 1.3.0, T21 1.0.33, uclibc 5.4.0)

- Codec backends present: `hwicodec_pf_h264e_t21_*` / `i264e_icodec_*`
  (H.264), `hwicodec_pf_jpege_t20_*` / `ijpege_*`, `hwicodec_pf_jpegd_t20_*`.
  No `h265e`, `i265e`, HEVC slice/VPS/SPS writer, CTU code or eprc h265
  variant exists in either library.
- H.265 symbols that do exist are the T30/T31 SDK API shell only:
  `IMP_Encoder_Set/GetH265TransCfg`, `IMPDbgFmtEncoderAttrH265*`
  (attribute dump), `update_h265_one_frmstrm` (stream bookkeeping).
- T23 `IMP_Encoder_CreateChn` (0x4e164): `enType == PT_H265` branches to
  0x4f32c, which only sets up the channel shell (mutexes, eventfd); no
  hwicodec/i264e instance is created.
- T23 `do_channel_process` (0x4a040): `PT_JPEG` -> `do_channel_process_jpege`,
  `PT_H264` -> H.264 path, `PT_H265` (0x4a098) returns without encoding,
  anything else logs "Playload Type %d is not support yet".
- T23 `IMP_Encoder_YuvInit/YuvEncode/YuvExit` log
  "not support h265 encode type" / "h265 enc type is not support".
- T21 has the same backend set (no H.265 codec); its frame dispatcher
  `on_encoder_group_data_update` (0x3ffcc) carries the same
  "Playload Type %d is not support yet" message.

So with the vendor library a `PT_H265` channel is created but never yields a
stream.

## Hardware

- Helix (soc_vpu, `HELIX_IOBASE`) is the H.264/JPEG engine; its command list
  is the T21-family list OpenIMP already builds (docs/T23_NATIVE_HELIX.md).
  Its CABAC contexts, 4x4/8x8 transforms and macroblock pipeline are H.264
  specific; there is no CTU, SAO or HEVC entropy mode to program.
- Ingenic's HEVC engine on this generation is a separate IP, **Radix**
  (`drivers/video/soc_vpu/radix`, `CONFIG_VPU_RADIX`, T30 only). In the
  3.10.14 kernel the T21 SoC headers carry `RADIX_IOBASE 0x13600000` but
  `IRQ_RADIX0` is commented out and no T21 board registers a radix device;
  the T23 SoC headers have no Radix base or IRQ at all. Thingino kernels build
  `CONFIG_VPU_HELIX=y`, `# CONFIG_VPU_RADIX is not set`.

No device probe of 0x13600000 was done: reading an unclocked or absent
block can hang the AHB bus.

## OpenIMP today

`p2_attr_codec_type` maps `PT_H265` to `IMP_ENC_TYPE_HEVC`; the T23 codec
glue uses the native Helix encoder only for `IMP_ENC_TYPE_AVC`, so an HEVC
channel falls to `HW_Encoder_Encode_Software`, which refuses non-H.264 and
produces no stream - the same visible result as the vendor. Possible
beyond-vendor change (not done, needs a decision): reject `PT_H265` in
`IMP_Encoder_CreateChn` on T20/T21/T23 with -1 so applications fall back to
H.264 instead of waiting for frames that never come.
